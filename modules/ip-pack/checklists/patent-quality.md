# 체크리스트: 특허 명세 품질 (적대적 자가검증)

> 당신은 **신선한(fresh) 컨텍스트**의 독립 검증자다. 생성된 명세서 초안을 **처음 작성한다는 자세로** 재검토하여 권리범위 약점·결함을 찾아 수정·예방한다(FIX & PREVENT, ETHOS 생성-검증 루프).

---

## 0. 법적·형식 (필수)

- [ ] 모든 산출물 **최상단에 법적 한계 고지**(출원 보조 초안, 전문가 검토 필요)가 있는가?
- [ ] 특허청 가이드 섹션이 모두 존재하는가? (명칭·기술분야·배경기술·발명의 요약[과제/해결수단/효과]·도면설명·실시예·청구범위·요약서)

## 1. 청구항 (권리범위)

- [ ] **독립항 최소 2개**(시스템/장치 + 방법)인가? (DoD)
- [ ] (권장) 컴퓨터 판독가능 매체(CRM) 독립항이 있는가? (SW 발명 보호)
- [ ] **종속항이 다수**이고 계층적으로 한정되는가? (권리 보강 fallback)
- [ ] 독립항이 **불필요하게 좁지 않은가**?(과한정 → 회피 용이) / 너무 넓어 선행기술에 걸리지 않는가?
- [ ] 종속항이 추가 한정(구성·조건·수치범위·실시형태)을 실제로 더하는가? (무의미 중복 금지)

## 2. 용어 일관성 (antecedent basis)

- [ ] 명세서 본문·청구항·도면 부호에서 **동일 용어**를 쓰는가?
- [ ] 청구항 첫 등장 구성요소가 본문·도면에 **정의/뒷받침**되는가? (antecedent basis 확보)
- [ ] "상기(said)" 인용이 선행 구성요소와 정확히 대응하는가?

## 3. 실시가능성 (enablement)

- [ ] 통상의 기술자가 **재현 가능**하도록 구성·동작·데이터흐름이 구체적인가?
- [ ] 청구항의 모든 구성요소가 실시예에 **뒷받침**되는가? (written description)
- [ ] 도면 부호가 본문·청구항·도면에서 **일관**되게 매핑되는가?

## 4. 신규성·진보성

- [ ] 각 발명의 신규성/진보성 논거가 있는가?
- [ ] **통상기술자 반론**을 제기하고 재반박했는가? 반박 불가 약점을 리스크로 기록했는가?
- [ ] 선행기술 노트에 **검색 한계**가 명시되었는가? (정식 서치 아님)
- [ ] 신규성 의심 포인트가 `[신규성 리스크]`로 플래그되었는가?

## 5. evidence_trace (출처추적)

- [ ] **모든 기술 서술·청구항 요소**에 `[Source: <path>#section]`가 있는가?
- [ ] 근거 없는 창작·추정 서술이 `[근거 미확보]`로 표시되거나 제거되었는가? (수치 날조 금지)
- [ ] `claims-map-kr.md`가 청구항↔설계요소↔도면부호↔Source를 빠짐없이 연결하는가?
- [ ] 상류 아키텍처 `source_hash` 기록으로 staleness 추적이 가능한가? (D3 정합)

## 6. 협업·산출

- [ ] `invention-disclosure-kr.md`를 **먼저 확정**해 Nathanael(연구팩)이 참고 가능한가?
- [ ] 모든 산출이 `outputs: .agent-team/05-ip/` 경로에만 기록되는가? (코어 비의존)

## findings 분류 (개선 권고)

- **(A) 치명 결함** (Critical — 반드시 수정): 독립항 부족·enablement 미달·무근거 청구항·한계고지 누락
- **(B) 권리범위 약점** (Enhancement — 보강 권장): 과한정 독립항·종속항 계층 부족·회피 가능성
- **(C) 형식·일관성** (Optimization): 용어 불일치·도면 부호 불일치·antecedent basis 흠결

> **성공 기준:** 전문가(변리사)가 본 초안을 받아 **최소 수정으로 출원 검토에 착수**할 수 있고, 모든 청구항이 설계 근거로 추적되며, 법적 한계가 명확히 고지된다.
