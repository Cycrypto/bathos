# 체크리스트: 스토리 컨텍스트 품질 (적대적 재검증)

## 미션

당신은 **신선한(fresh) 컨텍스트**의 독립 품질 검증자다. create-story가 생성한 스토리 파일을
**처음부터 다시 만든다는 자세로** 재검토하여, 원본 LLM이 놓친 **실수·누락·재앙**을 체계적으로
찾아 **수정·예방**한다. (단순 검증이 아니라 FIX & PREVENT.)

---

## 막아야 할 8대 치명적 실수

| # | 실수 | 설명 |
|---|------|------|
| 1 | **바퀴 재발명** | 기존 기능 재사용 대신 중복 생성 |
| 2 | **잘못된 라이브러리/버전** | 오래된·잘못된·deprecated 라이브러리 사용 |
| 3 | **잘못된 파일 위치** | 프로젝트 구조·명명 규칙 위반 |
| 4 | **회귀** | 기존 기능 파괴 |
| 5 | **UX 무시** | Jonnathan 디자인·인터랙션 누락 |
| 6 | **모호한 구현** | "어떻게"가 불명확한 지시 |
| 7 | **완료 거짓말** | 부정확/불완전 구현을 완료로 표시 |
| 8 | **과거 학습 무시** | 이전 스토리의 교훈·패턴 적용 안 함 |

---

## 재분석 절차 (5단계)

### 1단계 — 대상 이해

- 스토리 파일 로드, 메타데이터(epic_num/story_num/story_key) 추출.
- 현재 제공 가이던스 파악.
- **목표:** "이 스토리를 처음 만든다면 무엇이 필요한가?"를 baseline으로 설정.

### 2단계 — 출처 문서 철저 분석 (스토리를 처음 만든다는 자세로)

**2.1 에픽/스토리 분석:**
- 에픽 목표·비즈니스 가치·전체 스토리 맥락
- 우리 스토리 요구사항/AC·교차 의존성

**2.2 아키텍처 심층 분석:**
- 스택·버전 (실제 ADR·code-structure.md 확인)
- 코드 구조·명명 규칙
- API 패턴·데이터 계약
- DB 스키마
- 보안·성능 표준
- 테스트 표준·배포·통합

**2.3 이전 스토리 인텔리전스** (`story_num > 1`):
- Dev Notes·리뷰 피드백·생성 파일·확립된 패턴

**2.4 git 히스토리** (가능 시):
- 최근 커밋의 파일·패턴·의존성·결정

**2.5 최신 기술 리서치:**
- 사용 라이브러리 최신버전·breaking change·보안·deprecated (WebSearch)

### 3단계 — 재앙 예방 갭 분석

각 범주별 누락 식별:

| 범주 | 확인 항목 | 결과 |
|------|----------|------|
| 재발명 방지 | 기존 기능 활용 가능한가? | ✅/❌ |
| 기술명세 | 라이브러리·버전·breaking 명시? | ✅/❌ |
| 파일구조 | 경로·명명 규칙 준수? | ✅/❌ |
| 회귀 방지 | 기존 기능 파괴 가능성? | ✅/❌ |
| UX 정렬 | Jonnathan 디자인 반영? | ✅/❌ |
| 구현 명료성 | "어떻게"가 구체적? | ✅/❌ |
| 완료 기준 | AC 측정 가능·검증 가능? | ✅/❌ |
| 과거 학습 | 이전 스토리 패턴 주입? | ✅/❌ |

### 4단계 — LLM-Dev 최적화 분석

- **장황함**: 불필요한 반복 → 제거
- **모호함**: "적절히" "필요하면" → 구체화
- **컨텍스트 과부하**: 불필요한 정보 → 제거
- **핵심 신호 매몰**: 중요 경고가 묻혀 있는가?
- **구조 불량**: 스캔성 낮은 포맷 → 개선

### 5단계 — 개선 권고

findings를 4범주로 제시:

- **(5.1) 치명 누락** (Critical — 반드시 수정): [N건]
- **(5.2) 향상 기회** (Enhancement — 추가 권장): [N건]
- **(5.3) 최적화** (Optimization — 있으면 좋음): [N건]
- **(5.4) LLM 최적화** (Clarity): [N건]

## 성공 기준

개선된 스토리를 받은 dev 에이전트(Phillip/Andrew/Stephen)가:

- ✅ 따라야 할 기술 요구사항이 명확
- ✅ 이전 작업 컨텍스트를 활용 가능
- ✅ 안티패턴 예방으로 중복 회피
- ✅ 효율적 구현을 위한 종합 가이던스 보유
- ✅ 모호함·장황함 없는 최적 구조 (토큰 효율)

> **핵심:** dev 에이전트는 **이 스토리파일만** 본다. 그러므로 결함 없는 구현이 **불가피**해지도록 만든다.
